# WaveLab

WaveLab is a local HTTP service for tow-tank experiments. The original equipment and interlock pages expose a fixed commissioning diagnostic scenario. Operator measurements are a separate live data path.

Set `WAVELAB_DATA_DIR` to choose the archive directory (default `data/wavelab`). `POST /api/measured-runs` accepts `name`, `model_name`, `section`, and `carriage`. `POST /api/measured-runs/{id}/evidence` accepts `kind` (`wave_time` or `force`), `source_id`, finite `value`, and `recorded_at` in RFC3339 form. `GET /api/measured-runs`, `GET /api/measured-runs/{id}`, and `GET /api/measured-runs/{id}/analysis` return the supplied records and wave/force summary. Measurements are committed to `operator-measurements.json` before they are published in memory, and are reloaded when the service restarts. The archive does not automatically grant a safety permit or drive hardware.

The `internal/probe`, `internal/force`, `internal/permit`, `internal/carriage`, `internal/track`, `internal/wave`, `internal/absorber`, and `internal/journal` packages provide component logic for further work. Their diagnostic use does not imply that the original HTTP pages accept real sensor streams.

## Wave plans

The wave controller accepts one curve at a time; the plan library (`internal/plan`) lets staff save reusable wave-making plans. A plan records the target waveform (`frequency`, `amplitude`), its `duration_ms`, and the tank `sections` it may run on. `POST /api/wave-plans` saves a plan (send `id` to revise an existing one); `GET /api/wave-plans`, `GET /api/wave-plans/{id}`, and `DELETE /api/wave-plans/{id}` read and remove entries. Plans are committed to `wave-plans.json` before they are published in memory.

Before a plan is issued, `POST /api/wave-plans/{id}/preflight` with `{"section": "..."}` checks section applicability, equipment occupancy, in-flight tests on that section, and wave-maker availability without issuing anything. `POST /api/wave-plans/{id}/execute` runs the same checks, claims the section, and drives the wave controller for the plan duration; a failed check returns `409` with a recorded `rejected` execution. Executions are listed at `GET /api/plan-executions`, and `GET /api/plan-executions/{id}` reviews a single run, including the diff between the plan's ideal curve and the commands the controller actually issued (planned/actual counts, missing/extra commands, max/mean absolute setpoint error, and per-tick samples). Executions are committed to `wave-plan-executions.json`; a run interrupted by a restart is marked on next start. The `/plans` page shows the library and recent executions.
